EVORTALA

A national platform for monitoring and evaluating public service performance at BPOM, Indonesia's food and drug authority — used by every one of its 83 regional units. Platform nasional untuk memantau dan mengevaluasi kinerja pelayanan publik di BPOM, digunakan oleh seluruh 83 unit kerjanya di daerah.

The problemMasalahnya

BPOM evaluates the public service quality of its 26 Balai Besar POM, 37 Balai POM and 20 Loka POM every year. The evaluation spans several programmes — each with its own questionnaire, scoring rules and review flow — and the results have to be signed off officially. An older system existed, but its data model no longer matched how the evaluations were run, and it could not produce signed documents.

Setiap tahun BPOM mengevaluasi kualitas pelayanan publik di 26 Balai Besar POM, 37 Balai POM, dan 20 Loka POM. Evaluasinya terdiri dari beberapa program — masing-masing punya kuesioner, aturan penilaian, dan alur review sendiri — dan hasilnya harus disahkan secara resmi. Sistem lama sudah ada, tetapi struktur datanya tidak lagi sesuai dengan cara evaluasi dijalankan dan tidak bisa menghasilkan dokumen bertanda tangan elektronik.

Challenges & how we solved themTantangan & solusinya

An outbound HTTP client on a server without cURL.HTTP client keluar di server tanpa cURL.

The production server had cURL disabled for security reasons, which broke every library we would normally use to call the e-signature service and the One-Data API. Instead of asking for an exception, I wrote a small HTTP client on top of PHP stream wrappers with the same interface the rest of the code expected — including multipart uploads for documents and proper timeout and TLS handling — so the integrations work within the server's security policy.

cURL di server produksi dinonaktifkan demi keamanan, sehingga semua library yang biasa dipakai untuk memanggil layanan tanda tangan elektronik dan API One-Data tidak bisa berjalan. Daripada meminta pengecualian, saya menulis HTTP client kecil berbasis stream wrapper PHP dengan antarmuka yang sama seperti yang dipakai kode lainnya — termasuk upload multipart untuk dokumen serta penanganan timeout dan TLS — sehingga integrasi tetap berjalan sesuai kebijakan keamanan server.

Migrating years of legacy data.Migrasi data lama bertahun-tahun.

The new schema had to accept the history from the old system without losing scores that had already been published. I mapped the old tables to the new model, ran the migration repeatedly against copies of production, and compared totals per unit and per period before and after, so every difference could be explained before go-live.

Skema baru harus menampung riwayat dari sistem lama tanpa kehilangan nilai yang sudah dipublikasikan. Saya memetakan tabel lama ke model baru, menjalankan migrasi berulang kali pada salinan data produksi, dan membandingkan total per unit dan per periode sebelum dan sesudah migrasi, sehingga setiap selisih bisa dijelaskan sebelum go-live.

Many roles, one consistent workflow.Banyak role, satu alur yang konsisten.

Units fill in the evaluation, central reviewers score it, heads of unit approve it. Each module differs in the details, so the shared parts — periods, unit hierarchy, role checks and approval states — live in one foundation, and each module only adds its own questionnaire and scoring.

Unit kerja mengisi evaluasi, reviewer pusat memberi nilai, kepala unit menyetujui. Detail tiap modul berbeda, jadi bagian yang sama — periode, hierarki unit, pengecekan role, dan status persetujuan — ditempatkan dalam satu fondasi, dan tiap modul hanya menambahkan kuesioner dan aturan penilaiannya sendiri.

ResultsHasilnya

  • 437 users across all 83 units run their evaluations in one system.437 pengguna di seluruh 83 unit menjalankan evaluasi dalam satu sistem.
  • Evaluation documents are signed electronically instead of printed and signed by hand.Dokumen evaluasi ditandatangani secara elektronik, tidak lagi dicetak dan ditandatangani manual.
  • Legacy data moved to the new schema and the client's SIT findings were resolved before go-live.Data lama berhasil dipindahkan ke skema baru dan temuan SIT dari klien diselesaikan sebelum go-live.
What I'd take to the next project: agree on the data model with the client before building screens. Most late changes in this project came from evaluation rules that only surfaced during testing. Pelajaran untuk proyek berikutnya: sepakati model data dengan klien sebelum membangun tampilan. Sebagian besar perubahan di akhir proyek ini berasal dari aturan evaluasi yang baru muncul saat pengujian.
