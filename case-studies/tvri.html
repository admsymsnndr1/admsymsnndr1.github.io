On call for the World CupOn-call selama Piala Dunia

Keeping TVRI's FIFA World Cup 2026 news portal and its Android app running from the opening match to the final — and finding out why the site suddenly returned HTTP 500. ContextKonteks

For the tournament, TVRI ran a dedicated news portal and an Android app, both fed by the same CMS API. Traffic follows the match schedule: quiet most of the day, then sharp peaks around kick-off and final whistle. Within the first 28 days the app reached more than 21,000 device acquisitions and 10,000 monthly active users. My job was to keep everything up, investigate problems as they happened, and manage World Cup content in the CMS.

Selama turnamen, TVRI menjalankan portal berita khusus dan aplikasi Android yang sama-sama mengambil data dari satu CMS API. Trafiknya mengikuti jadwal pertandingan: sepi hampir sepanjang hari, lalu melonjak tajam di sekitar kick-off dan peluit akhir. Dalam 28 hari pertama aplikasi mencapai lebih dari 21.000 akuisisi perangkat dan 10.000 pengguna aktif bulanan. Tugas saya menjaga semuanya tetap berjalan, menyelidiki masalah saat terjadi, dan mengelola konten Piala Dunia di CMS.

The incident: HTTP 500 everywhereInsiden: HTTP 500 di mana-mana

  1. Symptom. The portal and the CMS API started returning HTTP 500 errors.Gejala. Portal dan CMS API mulai mengembalikan error HTTP 500.
  2. Narrowing down. The application code had not changed, so I looked below it: the logs pointed at the database layer failing to write.Mempersempit. Kode aplikasi tidak berubah, jadi saya memeriksa lapisan di bawahnya: log menunjukkan lapisan database gagal menulis.
  3. Root cause. MySQL temporary files had filled the server's 40 GB root partition. With no free space, queries that needed temporary tables failed, and every request that depended on them returned 500.Akar masalah. File temporary MySQL memenuhi partisi root server yang berukuran 40 GB. Tanpa ruang kosong, query yang butuh tabel sementara gagal, dan setiap request yang bergantung padanya mengembalikan 500.
  4. Escalation. I reported the cause to the infrastructure team with a recommended fix: move MySQL's temporary directory and data off the small root partition and add disk-usage alerts.Eskalasi. Saya melaporkan penyebabnya ke tim infrastruktur beserta rekomendasi perbaikan: memindahkan direktori temporary dan data MySQL dari partisi root yang kecil serta menambahkan peringatan penggunaan disk.
Lesson: an HTTP 500 is often not an application bug. Checking disk, memory and the database before touching code saved hours during a live event. Pelajaran: HTTP 500 sering kali bukan bug aplikasi. Memeriksa disk, memori, dan database sebelum menyentuh kode menghemat banyak waktu saat acara sedang berlangsung.
